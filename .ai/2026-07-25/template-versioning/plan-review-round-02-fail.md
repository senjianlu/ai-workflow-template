# Plan 评审:第 02 轮

## 问题清单
- [major] R-01 版本语义把 PATCH 限定为文案修正，遗漏了向后兼容的工作流缺陷修复，不能自洽地执行 SemVer。
  - 详情:定位：plan.md「README.md 版本与升级」的“版本语义”（约第 90-93 行）。方案将 hook、评审 schema 和流程步骤视为模板的兼容性协议，却没有为这些协议的向后兼容 bug fix 定义版本归类；它既不是“新增能力”的 MINOR，也不应因不兼容而成为 MAJOR。后续发版会无一致规则可依，影响 consumer 的升级判断。应改为 PATCH 覆盖向后兼容的缺陷修复（文案修正可包含其中），并保持 MINOR=向后兼容新增、MAJOR=不兼容变更。
- [major] R-02 README 的核心升级 diff 命令含未转义的尖括号占位符，复制执行会被 shell 解析为重定向；TC-03 又无法检出该错误。
  - 详情:定位：plan.md「README.md 版本与升级」中的 `git diff v<旧>..v<新>` 代码块（约第 101-107 行），以及 TC-03 命令（约第 207-230 行）。在 bash 中 `<旧>`、`<新>` 是输入重定向而非版本占位符，命令不能按文档所称“整体复制执行”；TC-03 仅提取该行并检查 11 个路径，错误命令仍会通过，未真实覆盖核心升级链路。应改用可执行的变量形式（如 `OLD_VERSION`、`NEW_VERSION` 并引用为 `"v$OLD_VERSION..v$NEW_VERSION"`），并让 TC-03 校验该无 shell 元字符歧义的命令形式及完整参数。

## 总评
方案已补齐独立模板克隆获取 tag 的链路，受管路径集合和证据档位契约也均有明确设计。但版本规则与可复制执行的升级命令仍存在核心正确性缺口，需修订后重评。
