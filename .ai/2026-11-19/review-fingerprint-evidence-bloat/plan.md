B 方案 = 把"每个未跟踪文件起一个 `shasum` 进程"改为批量内容哈希,检测强度
保持内容级,不改 docs/decisions/t0005 的安全决策。

**本任务交付**:`review.sh` 的 `workspace_hash()` 改为按参数容量分批的批量
实现(不再为每个普通文件单独启动哈希进程),指纹口径(类型 + 路径 + 可执行位 + 内容哈希)不变,附可重跑的回归
与性能测试;并以 1.4.1 补丁版本发布(仓内发版文件)。

## 背景与目标

生产侧(cscheap-frontend,证据见 `evidence/`)一次指纹约 11 分钟,每轮评审
在 Codex 前后各算一次,而 Codex 本身只用 2 分 43 秒:

- `evidence/untracked-files-cscheap-frontend.txt`:指纹覆盖 30130 个未跟踪
  文件,其中 28411 个在 `.ai/**/evidence/` 下,合计 6.1G;
- `evidence/timeline-review-round-02.txt`:`pre_hash` 用时 11 分 09 秒,期间
  `git ls-files` 早已列完、阻塞在管道上,耗时在逐文件的 `shasum < "$f"`
  (`shasum` 是 perl 脚本,每次启动约 20 ms)。

根因是每个普通文件单独启动一个哈希进程,不是内容读取量。目标:消除这项
逐文件开销,改为按参数容量分批处理,生产规模下的指纹耗时由"进程启动"主导
变为"读取内容"主导。

工具预检不是需求直接要求,但实现必需:批量实现依赖 `sha1sum`,缺失时若不
拒绝,内容哈希会静默为空,指纹退化为只看路径(fail-open)。调用点的失败
处理同理:不补的话,哈希运行期失败会让脚本以管道退出码结束,可能被读成
"评审 fail"(exit 1)而不是"执行异常"(exit 3)。

- `pre_hash` 与 `post_hash` 的比对逻辑、`__workspace_hash` 测试入口;
- `hash_excludes` 排除清单;已跟踪段(`git diff HEAD`);
- `plan-review.sh`(无工作区指纹);`docs/`(安全决策未变,t0005 不需回写)。

## 实现方案

**口径不变,编码方式变。** 未跟踪段由两个子段组成,各自先哈希再合并(沿用
现有"分段各自哈希、无跨段拼接歧义"的做法):

1. **元数据子段**:对 `git ls-files --others -z` 的每条路径,只用 shell 内建
   判断类型与可执行位,逐条 NUL 定界记账——符号链接记
   `symlink\0<路径>\0<链接目标>\0`,普通文件记 `file\0<路径>\0<x|->\0`。只有
   符号链接需要外部进程(`readlink`),数量与普通文件数无关。
2. **内容子段**:把非符号链接的路径统一加 `./` 前缀、以 NUL 定界批量交给
   `xargs -0 -r sha1sum -z --`,每条产出 `<sha1>  ./<路径>\0`。路径与内容哈希
   在同一条记录里绑定;`-z` 输出不转义、以 NUL 结尾,路径含空格、换行时无
   歧义。`./` 前缀是必需的:`sha1sum` 把操作数 `-` 当作标准输入,`--` 消不掉
   这层含义,不加前缀会漏检文件名恰为 `-` 的文件。

与现状逐项对照:

| 性质 | 现状 | 改后 |
|---|---|---|
| 覆盖对象 | 未跟踪文件,不按 .gitignore 排除,仅 `hash_excludes` 例外 | 同 |
| 符号链接 | 记链接目标,不跟随 | 同(符号链接不进内容子段) |
| 可执行位 | `[ -x ]` | 同 |
| 内容 | 逐文件 SHA-1 | 同为 SHA-1,批量计算 |
| 不可读文件 | 该文件无内容哈希,计算不中断、退出码 0 | 同 |
| 外部进程数 | 约等于文件数 | `xargs` 按参数容量分批,批数与路径总字节数成正比(30130 个文件约十几批);每个符号链接仍起一个 `readlink` |

**错误处理**:`sha1sum` 对个别文件失败(不可读)时 `xargs` 返回 123,此情况
容忍,保持"不中断",同批及后续批次的成功结果照常计入;其它失败(如
`sha1sum` 不存在返回 127、子命令以 255 退出使 `xargs` 返回 124)必须让
`workspace_hash` 以非 0 结束、不输出指纹。主流程两处调用点遇到非 0 时报错
并 exit 3:`pre_hash` 失败则不调用 codex,`post_hash` 失败则不发布评审文件。
主流程的既有工具预检同时补上 `sha1sum`、`xargs`,给出明确报错。

**指纹取值会变,但无兼容负担**:指纹只在单次 `review.sh` 运行内做前后比对,
不落盘、不跨运行比较。

**并发语义**:保留现有的尽力检测,不新增快照机制。列举与读取不是原子
快照——某次取指纹开始前已完成的改动会同时进入前后两个指纹,取指纹期间
"改了又改回"也可能得到相同结果;现状同样如此。

## 风险与回滚

- **`sha1sum` 可用性**:新增对 GNU coreutils 的依赖。脚本本已要求 Linux
  (util-linux、procps),coreutils 在同类环境必备;缺失时拒绝运行而不是降级
  (TC-05)。
- **口径漂移**:批量化改变了记录编码,若漏掉某一性质(可执行位、符号链接不
  跟随、路径绑定)会削弱检测;TC-01、TC-03 逐项覆盖。
- **生产规模的实际耗时未在本仓实测**:6.1G 内容每次仍要读一遍,预计为秒到
  数十秒级,取决于磁盘与缓存;TC-06 只证明进程启动开销被消除。若读取量仍
  不可接受,属非目标里的后续议题。
- **回滚**:单文件改动,`git revert` 即恢复逐文件实现;指纹不落盘,无数据
  迁移。
