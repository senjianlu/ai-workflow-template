# Plan 评审:第 01 轮

## 问题清单
- [major] R-01 两轮快照的排除口径不同时，核验轮会把仍在磁盘上的构建产物报告为已删除。
  - 类别:contract
  - 后果:进行中的任务升级到 1.5.1 后，即使未跟踪的 dist/x.js 一字未改，下一轮也会把它列为删除，并可能将上一轮保存的全文写入删除 diff。构建产物会再次出现在变化列表和轮间差异里。
  - 详情:plan.md:61–64、90–92 保留轮间差异规则，同时承诺排除项不会出现在变化列表和差异里。review.sh:489–499 合并两轮清单的路径，:511–516 将当前清单和 HEAD 均无记录的路径视为不存在，:577–580 将普通文件到不存在标为删除。应先按兼容的纳入口径对齐两轮输入，或在确认两轮口径不兼容时回退全量评审。
- [major] R-02 全量评审仍从原工作区选取未跟踪文件，与快照的排除口径不一致。
  - 类别:contract
  - 后果:首轮或回退全量时，评审者仍可能从 Git 状态中读到未被 Git 忽略的构建产物并据此提出阻断问题。该文件同时被指纹和清单排除，即使评审期间被重新生成，本轮结论仍可发布。
  - 详情:plan.md:61–64、90–92、138–141 将排除路径定义为评审范围外，但 review.md:1 要求评审原工作区的未跟踪文件，review.sh:837–861 的全量上下文也没有给出清单或选择规则。应让首轮和回退全量按本轮清单确定评审对象，使取材范围与所审内容一致性校验一致。
- [major] R-03 将两套 Git 排除规则直接合并，会让项目自定义的反选模式重新纳入原本被忽略的文件。
  - 类别:contract
  - 后果:例如，项目用 `.gitignore` 忽略 `*.log`，并在指纹排除清单中用 `--exclude='*.log'` 和 `--exclude='!audit.log'` 单独保留 `audit.log` 的完整性检查。按方案直接合并后，未跟踪的 `audit.log` 会被复制进评审快照，破坏原有忽略行为。
  - 详情:plan.md:78–86 要求在 `--exclude-standard` 之外追加 `hash_excludes`，并承诺原本被 Git 忽略的文件仍不进入快照。review.sh:41–52 允许增删项目模式，且指纹原本独立应用这些模式。按本机 Git 的 `gitignore(5)`，命令行模式优先于标准忽略规则，`!` 可以重新纳入文件。应分别判断两套规则，只保留两边都允许的未跟踪路径。
- [major] R-04 只跳过 `.claude/` 排除项，无法保住仍会命中其他模式的新 skill 和 hook。
  - 类别:convention
  - 后果:新增未跟踪的 `.claude/skills/dist/SKILL.md` 会命中默认的 `dist/` 模式。若这是核验轮新增的 skill，它不会进入本轮变化清单，评审期间对它的写入也不会被指纹或清单比对发现。
  - 详情:plan.md:78–88 承诺保留未被标准规则忽略的 `.claude/` 下的评审对象。review.sh:42–48 的 `dist/` 等未锚定目录模式同样匹配嵌套目录，:302–306 现有快照口径只排除 `.claude/settings.local.json` 和 `.claude/worktrees/`，t0015 第 4 项明确 skill 和 hook 属于评审对象。应为 `.claude/` 保留原有未跟踪路径筛选，并将新增的指纹排除筛选应用于其他路径。

## 总评
达成需求方面，两项修补均有交付路径，现有 Codex 调用也会沿用默认模型，但跨轮比较仍可能重新带入已排除的产物。

前提方面，现有 plan 指令确实经单个参数传递，现有轮间比较则会把清单和 HEAD 都缺失的路径推断为不存在。

总评建议保留 plan 指令限长设计，先修订快照路径选择和跨轮比较的契约，再按同一口径实现。
