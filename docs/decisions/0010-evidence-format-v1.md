# 0010:A 档证据改为 rawf-evidence v1 标准格式,格式完整性由机器核验,部分取代 0006

- 日期:2026-10-22
- 背景:0006 的档位制解决了"人工交互用例被一刀切打回"的误判,但 A 档
  "命令 + 完整原始输出 + 退出码"只有自然语言定义、没有标准形态,每个任务
  都在手搓自己的留证脚本(run_tcNN.sh、transcript.txt 各式各样),评审者
  每轮都要重新判断"这算不算完整"。四个 consumer 项目 332 个任务的统计:
  212 次首轮 fail 中 127 次含"证据格式"问题(缺命令、缺退出码、被截断),
  其中 37 次纯粹只因格式;第 2 轮起还有 46 条"证据仍不完整"在追。这些
  轮次几乎不涉及实现质量,却各消耗一轮 Codex 评审与一轮修复。
- 决定:
  - A 档证据只认一种形态——`evidence.sh` 包住命令产出的 rawf-evidence v1
    文件(头部必填字段 tc/cmd/cwd/git_head/started,正文为完整 stdout+stderr,
    尾部 exit(0..255)/finished/bytes,bytes 必须等于正文区字节数;权威
    定义在 review-standards.md「rawf-evidence v1 格式」)。同名文件拒绝
    覆盖(.ai/ 只增不改,重跑另起 label);中断仍写尾部;被包命令经 setsid
    自成会话,无锁、无共享状态、不写任务目录以外的项目路径,与评审脚本的
    会话/进程组查杀无交集。
  - `evidence-check.sh` 在 review.sh 启动 codex **之前**机器核验:以 plan
    用例表为基准对照记录(漏行、档位不符、空表、blocked),逐个 A 档证据
    文件核结构完整性;不通过 → review.sh exit 3、codex 不启动、不消耗
    评审轮次,补交清单由脚本直接开出;通过 → 报告注入评审 prompt。
  - 评审职责重划:格式归机器,内容归评审。评审对 A 档只核三件事(cmd 是否
    对应用例、exit 与正文是否符合 plan 写明的预期、记录与证据一致),
    **不再就格式提意见**;严重度改为:证据与预期/记录矛盾却报 pass →
    blocker(虚报),cmd 未覆盖用例场景 → major,格式 → 不列。
  - 非零退出码不等于失败:两种留证写法(直接包被测命令 / 包断言脚本)在
    plan 证据形态列声明,评审据此解读 exit。
  - 评审可读文件不设禁区,只给阅读顺序建议(先头尾、有疑点再深入)。
  - 兼容:plan 无 `evidence_format: v1` 的历史任务跳过机器核验,评审沿用
    0006 的旧规则自行核对格式。
  - 被否掉的备选:① 把大体量原始数据划入评审默认不读的子目录——用户否决,
    所有文件对评审开放按需读取;② 评审脚本自动截断/摘要证据——违背"完整
    原始输出"契约,且摘要本身又成为需要核验的对象。
- 影响:
  - review-standards.md「测试证据档位」A 档形态、「逐档核验规则」A 档条款
    以本条为准,0006 对应条款被部分取代;0006 的档位划分、B/C 档规则、
    不得降档等其余条款继续有效。
  - templates/plan.md frontmatter 增 `evidence_format: v1`;rawf-implement
    第 5 步改为 evidence.sh 留证并自跑 evidence-check;rawf-review 对
    "证据核验未通过"的 exit 3 不开新轮。
  - 预期效果:纯格式 fail 轮归零,混合 fail 轮中的证据条目消失,评审读
    证据的开销从通读降到头尾。
  - 残留风险:evidence-check 只核结构,"命令对不对、覆盖全不全"仍靠评审;
    被包命令若 fork 出不退出的后台进程会让留证器等待(A 档用例须自终止,
    与评审动作边界同一要求)。
