# 0011:范围自省不量化,只在固定位置提醒;追加类偏差须用户确认或入停车场

- 日期:2026-10-22
- 背景:四个 consumer 项目 762 份实现记录中 740 份"与方案的偏差"非空,
  大量是"plan 之外追加了 X""多加一个计数/多提三个函数""只加强不放宽"
  这类自我授权的扩张;737 轮实现评审只有 3 条提到范围外改动,因为评审
  prompt 没问;plan 与用户原始需求之间的偏移连记录位置都没有。用户要求
  "plan 和改修的 review 后总能自省是否偏移或让需求无端扩张",并明确不要
  量化(diff 预算、路径白名单、文件数阈值都过于复杂),由 agent 自判。
- 决定:
  - 自省落在模板与 prompt 的固定位置,保证每次都被问到,不设阈值:
    - plan.md 必填「需求原文」(用户原话 + 一句话交付物)与「非目标」
      (顺手项的合法出口);rawf-plan 摘要必带范围自省三问;
    - plan 评审固定问题:方案是否超出需求原文、非需求条目是否说明了实现
      必需、顺手项是否已入非目标;
    - 实现记录的偏差表类型固定为收窄 / 替代 / 追加,新增「停车场」;
      **追加类不得自行实现**,只能经用户确认或入停车场,"只加强不放宽"
      不是自授权理由;
    - 实现评审固定问题:diff 中是否有 plan 范围外且偏差表未声明的改动、
      偏差表中是否有未经确认的追加;
    - summary.md 新增「范围核对」节,rawf-report 就停车场与范围核对条目
      征求用户裁决。
  - 两级评审的范围结论写入输出 schema 的必填字段 `scope_findings`,渲染为
    评审文件的「范围核对」节,**不定严重度、不计入 pass/fail**,由用户裁决;
    这样范围问题不会被当成 minor 淹没,也不会误触发修复轮。
  - 被否掉的备选:① diff 预算(文件数/行数阈值)与路径白名单机器比对——
    有效但引入新脚本与 plan 机器可读清单,用户认为复杂度不值;② 把范围
    问题定为 major 自动进修复轮——范围是否可接受是用户的决定,不该由评审
    代判。
- 影响:
  - templates/plan.md、implementation-round.md、summary.md 增节;四个
    rawf skill 承接对应步骤;CLAUDE.md 硬规则新增"追加类偏差不得自行实现";
    schemas 与两个评审脚本的渲染增「范围核对」。
  - plan 缺「需求原文」或「非目标」在 plan 评审判 major(模板硬要求,与
    "未声明档位 → major"同级)。
  - 残留风险:提醒不是闸门,agent 仍可能把追加写成"替代"。缓解:评审的
    固定问题独立于实现者的自述,会把范围外改动列出;若日后出现系统性
    绕过,再考虑机器比对,届时新增决策取代本条。
