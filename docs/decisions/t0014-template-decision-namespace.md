# t0014:模板决策改用 t 前缀独立编号,并划清派生仓里模板文件与项目自有文件的归属

- 日期:2026-11-10
- 背景:派生项目经 Use this template 创建,会带入模板当时的全部决策文件,项目
  决策接着往下编。模板 1.3.0 新增第 13 号决策时,三个派生仓(cscheap-telegram、
  cscheap-link、cscheap-catalog)都已有自己的第 13 号,同一个编号指向两份不同的
  决策;模板每新增一条都会再撞一次,各仓的项目决策起始号还随创建时的模板版本
  漂移。同一次反馈还指出:模板的 `CHANGELOG.md`、`logo.svg` 与 `.ai/` 任务历史被
  原样带进派生仓,却不在任何受管路径归类里,三个仓三种处理(反馈原文见
  `.ai/2026-11-10/consumer-feedback-1.3.0/evidence/from-catalog/README.md`)。
- 决定:
  1. **模板决策改名为 `tNNNN-<slug>.md`**,编号与旧号一一对应(旧第 1 号即
     `t0001`),后续从 `t0014` 续编;纯数字 `NNNN` 整段留给派生项目,新项目的
     项目决策自第 1 号起编。模板仓库自身只新增 `t` 系列。
  2. **`t` 系列列为受管路径的「可整体替换」类**:受管文件(CLAUDE.md、脚本)
     引用它们,派生仓必须持有;派生项目不新增、不修改 `t` 系列。
     `docs/decisions/README.md` 列为「需人工合并」——派生仓在其中维护自己的
     决策索引。
  3. **存量仓不改自有编号**:升级时删除带入的模板旧文件(按写死的 13 个完整
     文件名,不从新版 `t*.md` 反推)、拷入 `t*.md`;从第 13 号起编的项目决策
     保持原号,前面的空号不补。
  4. **历史不回改**:模板仓 `.ai/` 历史记录与 CHANGELOG 旧条目里的旧编号保持
     原样,对应关系写在 `docs/decisions/README.md`「沿革」。
  5. **新增第三类归类「项目自有,创建后即脱钩」**:`CHANGELOG.md`、`logo.svg`、
     `.ai/` 下的任务目录、`docs/decisions/` 纯数字系列。README「开新项目」增加
     一步,要求创建后重置或清理它们;模板升级不触碰这一类。
  - 被否:规定项目决策从固定高位(如第 100 号)起编、模板占用低位——不用
    改名,但两类决策仍混在同一编号空间,且救不了已撞号的存量仓(用户裁决:要
    彻底区分);子目录 `docs/decisions/template/`——引用路径变化更大,且派生仓
    的决策索引要跨目录;前缀 `a`——没有含义,`t` 取 template。
- 影响:13 个决策文件改名,README、CLAUDE.md、AGENTS.md、review-standards.md、
  四个流程脚本与 gate-review.sh 的注释、`.gitignore` 的注释同步改引用(脚本只改
  注释,行为不变)。派生仓升级到 1.4.0 时须按 CHANGELOG 升级指引迁移决策目录,
  否则受管文件里的 `docs/decisions/tNNNN` 是死链(不影响任何闸门运行)。
